# 受控试行内容批次确认与发布决定

产品规格 13.1、18.1 要求分别记录内容维护者的“内容批次确认”和产品负责人的
“受控试行发布决定”。两类记录的数据在
[`apps/server/src/acceptance/decisions.ts`](../../apps/server/src/acceptance/decisions.ts)，
由 `checkTrialDecisions` 机械校验：角色必须不同、都必须包含非授权边界声明、
内容批次确认必须绑定当前激活批次，且记录中不得出现暗示已正式审定或机关授权的表述。

> 两类记录均**不代表**法制审核、正式内容审定或机关授权。它们只说明内容维护者
> 与产品负责人已按受控试行门槛完成内部确认，不构成对外的正式发布承诺。

## 内容批次确认

- 角色：受控试行内容维护者
- 范围：`release-trial-0001`
- 时间：2026-09-29
- 内容：确认本次激活批次中的法源均为现行有效、可核验的公开正式规范；
  十组派出所重点案情与首批文书范例均已具备独立版本、适用条件、依据、
  失效与禁用测试结果，并满足发布门槛。
- 边界：不代表法制审核、正式内容审定或机关授权。
- 引用：`release-trial-0001`、`docs/acceptance/trial-release-result.json`

## 受控试行发布决定

- 角色：受控试行产品负责人
- 范围：受控试行启动
- 时间：2026-09-29
- 内容：仅在硬门槛全部满足、发布检查通过且未触发停止条件时，决定以定向
  不公开网址开始受控试行。本记录不预先断言硬门槛已经满足；任何硬门槛失败
  或触发立即停止条件时，必须停用受影响功能。
- 边界：不代表法制审核、正式内容审定或机关授权。
- 引用：`release-trial-0001`、`docs/acceptance/trial-release-result.json`

## 与发布检查的关系

`gate-trial-decisions` 门槛要求两类记录同时存在且边界表述正确；同时
`gate-release-readiness` 要求使用与数据说明已替换全部占位信息，`gate-manual-evidence`
要求真实设备记录完成。任一不满足时 `npm run release:acceptance` 明确阻断。
