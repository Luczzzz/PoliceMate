# 事故责任研判意见结构调整

## 调整目标

- **层级合理化**：【责任认定】成为唯一重点，其他三节为支撑性内容
- **重点鲜明化**：责任认定放在首位，包含结论与关键理由
- **内容精简化**：事故概况改为关键事实，后续程序建议改为程序要点

## 旧结构（调整前）

```
一、事故概况
2024年X月X日傍晚18时许，在城南路口，小客车驾驶人甲由东向西直行通过路口，电动自行车骑行人乙由南向北左转进入路口，两车在路口中心位置相撞，乙受轻伤。路口有信号灯，甲方称当时为黄灯，乙方称当时为绿灯。现场监控显示甲方进入路口时为红灯。

二、责任认定
根据现场监控和双方陈述，甲方在红灯时进入路口，违反交通信号灯规定，是事故发生的直接原因，应承担全部责任；乙方按绿灯信号正常通行，无违法行为，无责任。这只是研判意见，最终以官方认定为准。

三、法律依据
《道路交通安全法实施条例》第38条：红灯亮时，禁止车辆通行。
《道路交通安全法》第76条：机动车发生交通事故造成人身伤亡、财产损失的，由有过错的一方承担责任。

四、后续程序建议
1. 需制作《道路交通事故认定书》，应当在制作道路交通事故认定书前，召集各方当事人到场，公开调查取得证据。
2. 道路交通事故认定书应当在十日内制作完成，送达当事人。
3. 告知当事人复核权利：当事人对道路交通事故认定有异议的，可以自道路交通事故认定书送达之日起三日内，向上一级公安机关交通管理部门提出书面复核申请。
4. 核对现场监控录像、当事人陈述与现场照片，确保证据链完整。
5. 如有人员伤亡，需同步处理伤情鉴定与赔偿调解事宜。
```

**问题**：
- 事故概况重复了问答记录，民警已经看过
- 责任认定不够突出，被埋在中间
- 后续程序建议太啰嗦，列出了过多细节步骤

## 新结构（调整后）

```
【责任认定】
甲方承担全部责任，乙方无责任。

理由：
1. 甲方在红灯时进入路口，违反交通信号灯规定
2. 乙方按绿灯信号正常通行，无违法行为
3. 现场监控证实上述事实，双方陈述与监控一致
4. 甲方违法行为是事故发生的直接原因
5. 这只是研判意见，最终以官方认定为准

法律依据
《道路交通安全法实施条例》第38条：适用于本案，因甲方违反红灯信号。
《道路交通安全法》第76条：明确过错责任原则，甲方有过错应承担责任。

程序要点
1. 需制作《道路交通事故认定书》，10日内送达当事人
2. 告知当事人复核权利（3日内可申请复核）
3. 核对监控录像、当事人陈述与现场照片，确保证据链完整

关键事实
• 甲方由东向西行驶至路口时，信号灯为红灯
• 甲方未停车，直接进入路口
• 乙方由南向北行驶，信号灯为绿灯
• 碰撞发生在路口中心位置
• 现场监控视频证实上述经过
```

**改进**：
- 【责任认定】用【】包围，视觉上最突出
- 结论单独成段，一目了然
- 理由分条列出，便于快速扫描
- 法律依据每条一行，含简短适用说明
- 程序要点只保留3条关键动作
- 关键事实只提取对责任认定有决定作用的5个事实

## 验收要点

人工验收时，检查实际生成的研判意见：
1. 【责任认定】是否在第一位？
2. 责任划分结论是否单独成段？
3. 理由是否分条列出（3-5条）？
4. 法律依据是否每条包含"法源+条号+简短说明"？
5. 程序要点是否精简（不超过5条）？
6. 关键事实是否只提取决定性事实（不超过5条）？
