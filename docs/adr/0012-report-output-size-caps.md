# ADR-0012：限制报告输出体量，换取 60–90 秒内出报告

- 状态：已接受
- 关联：ADR-0009、ADR-0010、ADR-0011；部署端日志第 2、3 项。

ADR-0011 之后单次 report 输出约 41k–47k 令牌，耗时 149–245 秒，整次提交 180–310 秒。解码吞吐没有变，变慢的根因是输出体量，而不是网络或 Dify 开销。决定：在提示词和模型输出 Schema 里给各部分加数量上限，目标是 report 节点中位耗时 ≤ 90 秒（约 15k 令牌内）。不换模型，不做异步化。

## 约束

- 上限：模块 `items` ≤6 条（每条 ≤80 字）、`traceLinks` ≤4 条且只保留被引用的、`evidenceItems` ≤8、`interviewItems` 每角色 ≤4（合计 ≤12）、`participantBehaviorSummary` ≤6、`documentTasks` ≤5、`factLimitations` ≤5、法条原文只带条号与 ≤100 字关键句。
- 上限只约束“数量”，不得删除六模块、研判速览或必须出现的结论字段。
- 首版取值，以实测调整；达不到目标时再收紧一档，不先换模型。

## 实现取舍

- 上限写进 `dify-report-result.json`（模型输出 Schema，`maxItems`）与提示词；后端校验用的 `dify-report.json` 由 `scripts/dify-schema.ts` 去掉 `maxItems`，模型偶尔多出一条不让整份报告失败，由显示层折叠。字符数上限只在提示词里，不入 Schema。
- 提示词版本提升到 `actionable-analysis-v2`（Schema 变化，部署端需同步更新 Dify 节点，旧工作流在新后端下被拒）。
- 代价：报告变短，法条原文只剩关键句；需要完整条文的人仍可按条号查原文。
- 与之配套的前端超时天花板（420/410/360 秒）暂时保留，待实测稳定后再下调。
- 异步化（先返回提取快照、报告后台生成加轮询）本次不做，达不到目标再另开。
