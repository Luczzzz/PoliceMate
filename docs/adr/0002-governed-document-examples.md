# ADR-0002：受治理文书范例的读取时状态门控与确定性测试内容

- 状态：已接受
- 日期：2026-09-27
- 关联：`#28 交付受治理的文书范例功能`，产品规格第 9、13、16.2、17 节

## 背景

产品规格要求文书范例是只读、可追溯的制作指导，并且必须证明：失效内容不能通过
列表、检索、缓存或历史链接继续展示。基线（ADR-0001）只提供了 `/documents`
入口和一个“合格范例数量”的替身字段，没有内容模型、发布批次或状态门控。

第 28 号切片需要在不引入真实法源和正式内容的前提下，打通“法源 → 受治理内容项 →
不可变发布批次 → 浏览/检索/筛选/只读详情”的完整链路，并覆盖失效与旧链接阻断。

## 决策

1. **内容模型分层**。`apps/server/src/content/` 内区分三类记录：法源记录
   （`LegalSourceRecord`）、文书范例变体记录（`DocumentExampleRecord`）和不可变
   内容发布批次清单（`ContentReleaseManifest`）。法源效力状态与内容状态严格分离；
   第一版没有 `approved`，只有 `trial` 内容可以进入生产检索。

2. **读取时状态门控**。列表、检索、打开详情和跟随旧链接都重新计算可用性，
   判定顺序为内容状态 → 激活批次白名单 → 依赖法源效力 → 核验期限。内容级的
   实际到期时间取自身期限与全部依赖法源期限中最早的一个（任一法源更早到期时内容
   随法源到期）。不做检索结果缓存；`/api/*` 响应统一 `cache-control: no-store`。

3. **批次原子激活与回滚**。批次清单一经激活即深冻结，只能整批切换。激活前校验
   每个内容项的版本、状态、测试结果与法源效力；任一失败则整批拒绝，上一完整批次
   保持激活。回滚只是切换到历史清单，历史版本不进入生产检索。

4. **旧链接语义显式化**。详情端点用三种结果区分“可展示”“已失效”“从未存在”：
   未知标识返回 404 `not_found`，曾存在但被门控阻断返回 410 `content_unavailable`。
   H5 据此显示“当前内容已经失效”，不回退到缓存或半成品正文。

5. **入口停用失败关闭**。总开关或文书入口开关关闭时，后端同时阻断列表内容与
   详情正文，而不是只让首页入口卡片降级；无法确认禁用是否生效时默认阻断。

6. **确定性测试内容只存在于替身边界**。第 28 号切片交付功能，不交付正式内容。
   测试内容（法源与范例统一带“[测试]”/“[测试法源]”标记、无官方链接）位于
   `providers/fixture.ts` 引用的 `content/fixture-content.ts`，只用于演示与验收。
   正式首批内容由后续内容发布工作替换，并重新走核验与发布门槛。

7. **检索词只留在当前页面内存**。H5 一次性读取当前激活批次的门控索引，关键词、
   程序类别、办理阶段和文书类型筛选都在页面内完成。检索词不进入 URL、后端请求、
   `localStorage`/`sessionStorage` 或内容日志。

8. **相邻变体同样经过门控**。详情页只展示当前批次中仍然合格的相邻变体，
   失效变体不会因为出现在详情里而绕过状态门控。

## 后果

- 后续真实内容接入只需替换内容源实现，门控、批次、API 与页面无需重建。
- 检索与筛选规模受激活批次大小限制（第一版上限 12–15 个变体），因此页面内
  检索是可行且最有利于隐私的实现；若未来批次显著增大，需要重新评估服务器端检索
  及其对“检索词不入 URL/日志”的影响。
- 测试通过 `/api/test/fixtures` 的治理开关（`exampleStatusAll`、`exampleStatus`、
  `legalSourceStatusAll`、`examplesExpired`）验证下架与旧链接阻断；该接口只在
  `PM_ENABLE_TEST_CONTROLS=1` 时挂载，生产默认关闭。
- 状态门控在每次请求重新计算，代价是每次读取都做一次全量过滤；在受控试行的
  内容规模下可以接受。
