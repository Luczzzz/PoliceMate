# ADR-0016：新增交通事故责任认定辅助，模型决定追问、后端只做转述与校验

- 状态：已接受
- 关联：ADR-0004（会话隐私与传输加固）、0007（受控试行验收与发布门槛）、0012（报告长度上限）、0014（直连 LLM 提供者）、0015（流式纯文本分析）。`dify` 模式不实现多轮问答，因此该入口在 `dify` 模式下不可用（`dify` 模式已由 ADR-0017 移除）。

## 背景

一线民警处理交通事故时，往往要先在脑子里把「谁在什么位置、朝哪个方向、有没有让行、
信号灯或标志标线状态、有没有伤亡」这类关键事实问清楚，才能谈责任划分。现有「案情分析」
是按一段自由案情一次性给结构化报告，既不适合这种逐项问清的节奏，也不针对事故场景。

目标交互是：民警先写一段脱敏的事故概况，系统就关键事实逐轮追问，直到信息足够或民警
直接要结果，最后给出一份纯文本研判意见。这要求模型来判断「还缺什么」，而不是后端预设
一棵问题树——事故场景的分支太多，预设树既写不全，也会问无关问题。

## 决策

1. **独立入口。** 首页新增第三个同级入口 `accidentLiability`，与案情分析、文书范例并列，
   使用与其他入口完全相同的卡片结构和视觉强度。可用性由后端外壳给出，页面不得推断。
2. **独立开关与失败关闭。** 新增 `PM_ACCIDENT_LIABILITY_ENABLED`（默认开启）。总开关关闭、
   入口开关关闭、边界未实现多轮问答、或分析服务不可用时，入口与 API 都失败关闭（入口显示
   原因，API 返回 503），不静默回退到案情分析。
3. **模型决定追问。** 外部边界只有一个方法 `consultAccidentLiability`，输入是完整问答记录、
   `forceReport` 标志与本次适用的受治理法源，输出只能是
   `{kind:"question"|"report", text}` 之一。后端不预设问题分支、不做多问题拆分。
4. **输出形状不符即整体失败关闭。** 边界返回非法结构、空文本，或在 `forceReport` 为真时
   仍返回追问，后端最多按 `PM_MAX_PROVIDER_ATTEMPTS` 重试，仍失败则返回 503，且不把这一轮
   写入会话。已产生的会话保持原状，民警可重试。
5. **纯文本产物，无结构化校验。** 研判意见是一段纯文本，按「【责任认定】／法律依据／
   程序要点／关键事实」四个小节组织。其中【责任认定】是唯一重点，第一段只写责任划分结论，
   然后分条列出3-5个关键理由；「法律依据」每条写成「法源+条号+简短适用说明」；
   「程序要点」只列关键动作（不详细步骤）；「关键事实」只提取对责任认定有决定作用的3-5个事实。
   这四个小节由提示词要求，不是 Schema 约束；后端不做条号校验，
   沿用 ADR-0015 的口径：提示词里放入受治理法源并要求只引用其中条文，但这是提供材料，不是校验。
6. **报告不是一轮问答。** 问答记录只含民警的概况与回答、以及系统的追问；报告单独作为 `report`
   字段返回。两者一起展示，报告以问答记录为事实来源。
7. **只能补充，不能改写。** 民警可以追加回答，但不能修改或删除已经发生的回答。若发现之前说错，
   只能在后续回答里更正。生成报告后阶段变为 `report_ready`，再追加回答返回 409。
8. **民警可以随时要结果。** `POST …/report` 以 `forceReport=true` 调用边界，即使模型认为信息不足
   也必须直接给报告。
9. **会话只在短暂运行内存。** 会话默认 30 分钟空闲后丢弃；不写数据库、日志或 URL，第三方分析
   工具只收到问答文本本身。接口只有新建、追加回答、要求报告和惰性清除（`DELETE`）四个；
   不提供读取会话的 `GET`，前端不写 sessionStorage，刷新或关闭页面后不可恢复。固定边界声明
   由后端附带，不经过模型。
10. **输入与输出上限。** 事故概况上限 10,000 字符、追问回答上限 2,000 字符，超限或缺内容直接
    拒绝，不截断输入；研讨意见超过 12,000 字符时截断并显式标注（沿用 ADR-0012/0015 思路）。
11. **遥测只记非内容元数据。** 新增 `accident.consult` 事件，只记耗时、尝试次数、结果状态与
    `force_report`／`question`／`report` 这类固定枚举；事故概况、回答与报告正文都不进日志。
12. **只用当前有效法源。** 进入提示词的受治理法源先按 `status === "current"` 过滤，与案情分析
    一致；已废止、效力不明或已到期的条目不得成为研判依据。

## 已知风险

- **模型可能写错责任划分与条号。** 没有事实快照、没有条号校验，也没有「先校验后采用」，
  民警必须自行核对现行规定；争议或重大事故要请示法制部门。
- **责任认定本身是敏感结论。** 产品把它降级为「研判意见」，但民警仍可能照抄。因此入口文案、
  固定边界声明与词汇表都反复划定边界，验收也要求人工比对一次。
- **内容治理强度低于结构化报告。** 该功能不经过受治理内容项的逐条链路校验，只是把法源材料
  放进提示词；这削弱了「可解释链路」的可验证性。
- **多轮问答的等待时间不确定。** 每次追问都是一次完整模型调用，超时与失败按第 4 条处理。
- **当前受治理批次可能没有交通类法源。** 「法律依据」小节因此可能写成「本次没有可引用的受治理
  法源」。这是诚实的降级，不是缺陷；在内容维护者把《道路交通安全法》等国家级法源连同条文原文
  与校验记录加入受治理批次之前，该功能不应被宣传为能给出具体条号。

## 验收

- 黑盒：首页第三个入口可用且可点击；提交事故概况后出现第一个追问；回答后出现四小节研判意见与
  固定边界声明；民警可主动直接生成；服务不可用时入口与直达页面都显示暂不可用。
- 单元：入口可用性独立降级；非法边界输出失败关闭且不写入会话；生成报告后追加回答被拒绝；
  遥测不含事故概况、回答与报告正文。
- 人工：用虚构事故个案逐条比对研判意见中的条号引用与仓库法源，结果记入
  `docs/acceptance/manual-evidence.md`。
