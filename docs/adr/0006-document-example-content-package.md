# ADR-0006：首批试行文书范例内容包与阶段、高风险覆盖门槛

- 状态：已接受
- 日期：2026-09-29
- 关联：`#36 发布首批六个文书范例`，产品规格第 3.4、9、13.7、16.2、17 节，
  ADR-0002（受治理文书范例）、ADR-0005（内容包与发布门槛）

## 背景

ADR-0002 打通了“法源 → 受治理内容项 → 不可变发布批次 → 浏览/检索/只读详情”
的完整链路，但第 28 号切片只交付了功能：文书范例是统一带“[测试]”标记的
占位内容，法源是“[测试法源]”，用于验证门控与旧链接阻断，不能作为试行内容
发布。产品规格 3.4 要求在受控试行开始时发布至少六个通过全部治理验收的文书
范例变体，并覆盖接报或受理、调查取证和至少一个高风险程序环节。

第 36 号切片需要在不改动既有门控、批次、API 与页面的前提下，交付首批具有
可靠公开正式依据的文书范例，并把发布检查从“范例数量”扩展到“阶段与高风险
环节覆盖”。

## 决策

1. **新增独立文书范例内容包 `content/document-example-content.ts`**。内容包与
   重点案情内容包（ADR-0005）并列，导出法源记录、范例变体、发布门槛场景清单、
   必需办理阶段与内部覆盖矩阵；`fixture-content.ts` 只负责把它们与重点案情
   内容包整批装配进同一个不可变发布批次。门控、检索、详情与批次激活逻辑不变。

2. **首批发布七个变体，覆盖三个必需阶段**：
   - 接报与受理：受案登记表、受案回执；
   - 调查取证：询问笔录（行政）、调取证据通知书、讯问笔录（刑事）；
   - 高风险程序环节：证据保全决定书（先行登记保存）、检查证。

   七个变体分别属于行政或刑事程序，具有独立版本、内容状态、文书类型、
   适用案情标签、适用对象、触发条件、前置条件、不适用情形、必须核验事实、
   相邻变体区别、结构分段、注释式虚构示例、制作要点、常见错误与高风险提醒。
   沿用既有内容模型：触发条件由 `applicableScenarios` 承载（统一表述为
   “…时。”），前置条件与选择前必须核验的事实分别由 `prerequisites` 与
   `preflightChecks` 承载。

3. **法源限定为国家公开正式规范，只用有正式依据的候选方向**。首批两个法源
   为公安部部门规章：《公安机关办理行政案件程序规定（2020年修正）》
   （公安部令第125号发布，第132、149、160号令修正）与《公安机关办理刑事
   案件程序规定（2020年修正）》（公安部令第127号发布，第159号令修正），
   官方链接指向中国政府网公开全文页。没有可靠公开正式依据的候选方向
   （例如只在网络模板或内部文书中出现的“不予受理告知书”）不发布。
   每个变体的“正式格式或制作规范来源”绑定决定该文书必备内容的现行条款
   （`formatSource`）；本批不引用无法公开核验的内部文书式样。

4. **统一的纯虚构示例体系**。示例人物、单位、地点、号码、时间和金额由
   `DOCUMENT_EXAMPLE_FICTIONAL_SYSTEM` 统一定义，所有分段注释式示例只使用该
   体系（示例派出所、示例县公安局、示例路示例小区、张三/李四/王五、以“示”
   开头的虚构文书编号），不以真实文书简单打码，不出现身份证号、手机号、
   真实姓名或门牌号。测试对全部示例文本执行虚构化与敏感信息检查。

5. **核验期限按内容性质区分**。受案登记表、受案回执直接关系受立案条件与
   刑事/行政分流，适用产品规格 13.7 的 30 天重新核验期限；其余文书范例
   与其依赖法源适用 90 天期限。任一时间不可解析时沿用既有门控失败关闭。

6. **发布检查新增文书范例阶段与高风险覆盖门槛**。`checkReleaseReadiness` 接受
   `documentExampleCoverage`：必需办理阶段必须各有合格范例，且合格范例中
   至少一个带有“高风险环节”标签，任一不满足即阻断发布。脚本从当前激活批次
   的合格索引派生阶段集合与高风险数量，与“至少六个合格范例”和十组重点案情
   覆盖门槛共同构成受控试行硬门槛。

7. **内部“派出所重点案情 × 文书范例”覆盖矩阵**。
   `DOCUMENT_EXAMPLE_COVERAGE_MATRIX` 记录十组重点案情与已发布变体的对应关系，
   由 `document-example-content.test.ts` 在发布前执行覆盖检查（十组齐全、
   只引用已发布变体、每行覆盖全部必需阶段、无未引用变体）；矩阵为只读，
   不进入列表、详情或任何用户可见投影，也不作为覆盖等级或推荐。

8. **测试内容边界不再承担试行内容**。`fixture-content.ts` 移除“[测试]”占位
   范例与“[测试法源]”，改由本内容包提供试行内容；发布批次 ID 改为
   `release-trial-0001`。治理开关（`exampleStatus`、`exampleStatusAll`、
   `examplesExpired`、`legalSourceStatusAll`、`legalSourcesExpired`）继续用于
   验证紧急禁用、到期与旧链接阻断。发布门槛场景的实际检查与
   `testResults` 声明一一对应，避免结果自证。

## 后果

- 文书范例入口现在展示有公开正式依据的试行内容；后续新增变体只需在内容包中
  增加记录、场景与法源，并复用既有门控、批次与发布门槛。
- 首批内容以核心程序文书为主，行政与刑事程序都有覆盖；高风险环节的
  `检查证` 与 `证据保全决定书` 在详情中明确要求人工核验，系统不自动作出
  检查、保全或者处置决定。
- 文书范例的正式性取决于内容维护者的核验记录与公开法源，不代表法制审核、
  机关授权或者文书合格性判断；地方适用层与内部文书样式仍需另行授权盘点。
- 办理阶段与高风险覆盖门槛把“覆盖高风险环节”从人工确认变为可机械核验的
  发布阻断项；“高风险”本身仍由内容标签与人工复核表达，不由系统推断。
- 内容规模仍在第一版候选上限内；若批次显著增大，需要按 ADR-0002 的后果
  重新评估页面内检索与服务器端检索的取舍。
