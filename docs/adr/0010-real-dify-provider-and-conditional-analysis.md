# ADR-0010：真实 Dify 提供者与条件性分析保留

- 状态：已接受
- 关联：ADR-0004（会话、隐私与失败降级）、ADR-0005（重点案情内容包）、
  ADR-0008（直接分析）、ADR-0009（殴打伤害报告保留可执行内容）；
  产品规格第 7.2、10、12、13 节，`docs/deployment/dify-integration.md`

## 背景

第一版长期停在确定性 fixture：报告是模板文本，且"条件不足"会把初步定性、
受立案条件和法律依据三个模块一并替换为同一条不足提示并清空依据链路。
ADR-0009 只给殴打伤害类开了例外。用户反馈"过于谨慎、结果不清晰、有用内容少"，
并要求接入真实 Dify。

## 决策

1. **接入真实 Dify Workflow，且与 fixture 显式分离**。`PM_PROVIDER_MODE` 选择
   `fixture` 或 `dify`；生产默认 `dify`。真实模式在地址、应用密钥或允许的工作流
   版本缺失时失败关闭，**不自动回退 fixture**。单个 Workflow 用 `operation`
   区分提取与报告，凭据只存在于后端。
2. **版本与快照双向绑定**。请求携带 `contract_version`、`prompt_version`、
   `workflow_version`、`requestId`、`snapshotVersion`、`snapshotHash`、
   `contentReleaseId`；上游必须在输出中原样回传。任一不一致、`promptVersion`
   不是 `actionable-analysis-v1`、或报告正文字段与封装冲突时丢弃响应。
3. **契约由生成的 JSON Schema 机械校验**，而不是靠提示词自律。模块 ID 与标签、
   链路与 `factReferences` 的一一对应、`formal_basis` 与后端受治理法源逐字段匹配
   （含条款原文、版本、地域、核验日期）、证据与询问枚举、文书任务固定边界文案、
   `complete` 状态的法源与关键模块要求都由后端校验；模型不得自行声称事实"已确认"。
4. **可用性探测不运行模型**。检查应用类型为 Workflow 且 `operation`、
   `payload_json`、`contract_version`、`workflow_version` 四个输入变量齐全，
   结果短期缓存。
5. **条件性分析在真实分析下保留**。真实 Dify 分析的 `insufficient_facts` 不再清空
   初步定性、受立案条件与法律依据：关键模块保留模型给出且已通过校验的条件性内容
   与依据链路，总体状态、状态标签与事实限制仍然如实标注不确定性；
   `basis_unavailable`、争议/相邻方向、依据失效和生成失败继续整体降级。
   这取代 ADR-0009 “只适用于殴打伤害类”的范围，适用于全部受治理重点案情。
   fixture 保留原有保守降级作为确定性占位行为，不冒充真实分析。
6. **取消传播到 HTTP 层，但不宣称上游立即停止**。请求取消、清除会话或确认新
   快照时中止在途上游请求，并在返回前复核会话与快照哈希，丢弃迟到结果。上游
   被中止后模型是否仍在运行属于供应商边界，必须如实披露，不得声称已停止处理。

## 后果

- 真实分析质量取决于 Dify 工作流与提示词；契约测试与生成 Schema 是防止结构
  漂移的主要手段，修改工作流必须同步更新两者。
- `npm run dify:schema` 必须与类型定义一起提交，缺失或过期会让真实模式拒绝
  合法输出，属于刻意的失败关闭。
- 条件性分析保留意味着报告会更明确地给出方向与依据，但"未经确认"标签、事实
  限制和分支呈现承担了不确定性表达；不得把保留内容表述为已确定结论。
- fixture 仍用于开发与浏览器测试，不再是生产分析路径。
