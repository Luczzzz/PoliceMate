# ADR-0005：派出所重点案情内容包与报告法源限定

- 状态：已接受
- 日期：2026-09-28
- 关联：`#33 发布财产与经济类派出所重点案情内容包`，产品规格第 3.2、3.3、7、
  13、16.1、17 节，决策票据 #16、#18、#30

## 背景

产品规格把“派出所重点案情”定义为内部内容建设清单，要求十组案情各自具备
当前有效可核验的正式依据、核心分流条件、相邻案情区别、决定性事实缺口，
以及典型、相邻反例、决定性事实缺失和高风险边界场景，并能通过统一流程生成
可追溯的六模块报告，在事实或依据不足时保守降级（规格 3.2、16.1、17）。

第 28 至 32 号切片已经交付受治理文书范例、事实快照、六模块报告与安全边界，
但受治理内容只有法源与文书范例两类记录，分析报告也只会使用“当前可用的
任意法源”。第 33 号切片需要在不新建独立界面的前提下，交付财产与经济类
四组重点案情内容，并让报告确实受该重点案情的受治理法源约束。

## 决策

1. **新增第三类受治理内容记录：重点案情（`CaseFocusRecord`）**。它与法源
   记录、文书范例记录并列，具备不可变版本、内容状态、地域、依赖法源、
   起草/核验/发布/复核日期、维护者、变更说明与测试结果。重点案情同样进入
   不可变内容发布批次（`ContentReleaseManifest.caseFocuses`），激活前必须
   整批校验；沿用与文书范例一致的状态门控顺序：内容状态 → 批次白名单 →
   依赖法源效力 → 核验期限。

2. **内容模型显式区分“用户可见行为”与“内部建设清单”**。重点案情不建立
   独立页面，也不作为覆盖等级展示；它只参与法源限定、缺口判定与报告降级。
   内容记录包含分流条件、相邻案情区别、财产关系/占有状态/欺骗或隐瞒/
   主观状态/履约过程/资金流转/帮助行为/损失等要素说明和高风险边界。

3. **匹配只依据已确认事实，不解析自然语言结论**。`CaseFocusMatchRuleRecord`
   用候选事实中 `category=behavior` 的规范行为标签，加上事实原始表述中的
   线索词（`requireAnyHints` / `excludeHints`）做确定性匹配。电信网络诈骗与
   一般诈骗通过“是否出现电信网络线索”互斥区分，不依赖模型输出。只有
   “已确认、未排除、未被替代”的事实参与匹配。

4. **报告法源按命中重点案情限定**。后端在生成报告前把已确认事实交给受治理
   内容边界解析：命中重点案情且可用时只使用该案情的法源；命中但不可用
   （禁用、到期、依赖法源废止/失效/不明）时使用空法源；未命中时回退到通用
   法源，但只在依据足够时才允许形成初步意见。报告头部记录命中的重点案情
   ID 与版本（未命中为 `null`），便于追溯。

5. **决定性事实缺口按事实类别机械判定**。`CaseFocusGapRecord.factCategory`
   把一个缺口绑定到候选事实类别；本次分析不存在任何“已确认且未排除”的
   该类事实时，缺口即未解决。缺口未解决、或不能排除的相邻重点案情同时
   命中时，报告按规格 7.2 的保守顺序由后端降级；降级只改写关键模块状态与
   边界说明，不补写任何法律结论。

6. **降级顺序唯一且可测试**。`basis_unavailable` > `conflicting` >
   `insufficient_facts` > `complete`。降级只作用于支撑主判断的关键模块
   （初步定性分析、受立案条件分析、法律依据与可解释链路），并清空其法源
   链路；证据核查清单、分角色询问要点等程序性内容不受影响。

7. **真实内容与场景验收一起交付**。四组重点案情使用国家公开正式规范
   （刑法、治安管理处罚法、反电信网络诈骗法、民法典及相关司法解释与
   两高一部意见）。每组包含一个典型、一个相邻或不应命中反例、一个决定性
   事实缺失、一个高风险边界和一个失效禁用场景；场景验收通过分析引擎驱动
   “自由案情 → 已确认事实 → 事实快照 → 六模块报告”，并断言命中的重点案情、
   报告状态、决定性缺口与法源链路。

8. **紧急禁用与到期沿用既有门控**。`/api/test/fixtures` 增加
   `caseFocusStatusAll`、`caseFocusStatus`、`caseFocusesExpired`、
   `legalSourcesExpired` 控制项；内容发布检查新增重点案情覆盖门槛，
   任一必需重点案情不合格即阻断发布。

## 后果

- 后续重点案情内容包（#34、#35）只需新增 `CaseFocusRecord` 与场景，即可复用
  门控、匹配、降级与场景验收，无需改动产品界面。
- 重点案情的正式性取决于内容维护者的核验记录，不代表法制审核或机关授权；
  数额标准仍须按地区现行规定另行核对。
- 匹配依赖事实提取的行为标签质量；真实 Dify 接入后若行为标签体系变化，
  需要同步更新匹配规则并重跑全部重点案情场景（规格 13.6）。
- 报告法源被限定为重点案情依赖的法源，可能少于通用法源集合；这是
  “受治理内容支撑主结论”的预期结果，不是能力缺失。
