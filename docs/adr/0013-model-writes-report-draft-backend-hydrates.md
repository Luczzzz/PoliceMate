# ADR-0013：模型只写报告草稿，其余由后端补全

- 状态：已接受
- 关联：ADR-0010（第 3 条“契约由 Schema 机械校验”部分被本 ADR 改写）、ADR-0012；部署端日志第 2、3 项。

ADR-0012 只限制了各部分的**条数**，每条仍带完整结构。实际检查 report 输出 Schema（约 90 个字段）发现，模型在写大量后端本来就有的内容：每条依据链路整段回抄法源的 13 个字段（每模块至多 4 条、共至多 24 份）、每个枚举值旁再写一遍中文标签、文书任务里的固定边界文案、封装里的版本元数据。输出越长，整份 JSON 因一处语法错误作废的概率越高，而且这些回抄内容没有任何判断价值。

## 决策

1. 模型只输出 `ReportDraft`：判断性文字（标题、模块摘要与条目、条件与判断、证据与询问文字、研判速览）和标识（`factIds`、法源 `sourceId` 加条号 `article`、枚举值）。
2. 后端的 `hydrateReportDraft` 补全：模块名称、各类展示标签、法条的版本、标题、发布机关、文号、地域、日期、链接与条文原文、文书任务的程序类别名称、阶段名称和固定边界说明、`contentReleaseId`、`workflowVersion`。事实依据明细仍由 `attachReportFactReferences` 补齐。
3. 草稿引用的法源不在本次受治理清单、或条号不在该法源中，补全时直接失败，整份报告不予采用。原先“模型抄、后端逐字段比对”变为“模型只选、后端给值”，模型无法改写条文。
4. 提示词版本提升到 `actionable-analysis-v3`；旧工作流在新后端下被拒（503）。Dify `wrap` 节点不得再向报告结果写入 `workflowVersion`、`contentReleaseId`（草稿 Schema 不允许）。
5. 前端和对外的报告结构不变；内部契约版本号 `1.0` 不动，以免牵动前端请求头，以提示词版本区分新旧工作流。

## 取舍

- 代价：法条原文长度由后端决定，不再是模型挑的关键句；ADR-0012 里“法条原文只带条号与 ≤100 字关键句”的上限随之失效，改为后端给整条受治理原文。
- 好处：报告输出 Schema 从约 18.3 KB 降到 11.9 KB，且最大的重复块（法条回抄）消失；一类校验失败（回抄不一致）不再可能出现。
- ADR-0012 的数量上限、不换模型、本阶段不做异步化仍然有效；是否继续收紧以 v3 实测耗时为准。
- 后续：先实测 v3；再迁移到直连模型接口（另起 ADR），最后评估分段并行。
