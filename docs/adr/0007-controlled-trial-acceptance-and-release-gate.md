# ADR-0007：受控试行验收矩阵、演练与发布门槛

- 状态：已接受
- 日期：2026-09-29
- 关联：`#37 完成松警伴侣受控试行验收与发布门槛`，产品规格第 3.4、3.5、5.1、
  7.4、12.4、13.1、13.5、13.6、13.7、15、17、18 节，ADR-0004（会话、
  隐私与失败降级）、ADR-0005（重点案情内容包）、ADR-0006（文书范例内容包）

## 背景

第 27 至 36 号切片交付了可运行外壳、受治理文书范例、事实快照、六模块报告、
安全与失败降级，以及十组派出所重点案情与首批文书范例内容包。此时产品行为
已基本齐备，但缺少把「十组重点案情 + 至少六个文书范例 + 产品能力」组合成
可验证受控试行候选的收尾工作：AC-01 至 AC-34 的逐项可追踪验收、设备与
浏览器验收、紧急停止演练、内容批次回滚与重建演练，以及一个会在任一硬门槛
失败时明确阻断的发布检查。

这些要求分散在产品规格第 17、18 节，单靠人工清单容易漏项或悄悄删除场景。
需要一个版本化、可机械校验、且能产出可复现结果的验收与发布门槛。

## 决策

1. **验收矩阵作为版本化数据**（`apps/server/src/acceptance/scenarios.ts`）。
   AC-01 至 AC-34 逐项记录标题、规格章节、自动化测试引用、人工记录 ID 与
   演练 ID。`coverage.ts` 机械校验：34 项齐全不重复、每项至少一类证据、
   自动化引用能在测试文件中字面找到、人工记录与演练都被引用、规格章节在
   正文中存在。任何场景被删除都会让 `acceptance-matrix.test.ts` 失败。

2. **设备、浏览器、可访问性与性能记录结构化**（`acceptance/evidence.ts`）。
   区分 `automated-proxy`（确定性浏览器引擎/设备仿真）与 `manual`（真实设备）。
   真实 iOS Safari、真实屏幕阅读器与真实 4G 机型记录标记为阻断型，未完成前
   发布检查失败；不把人工记录伪造为通过。

3. **紧急停止与内容批次演练可执行**（`acceptance/drills.ts`）。15 项演练覆盖
   后端总开关、两个入口开关、法源废止/效力不明、单项撤回、重点案情禁用、
   内容与法源到期、无合格范例、状态无法确认时的失败关闭，以及内容批次原子
   激活失败、整体回滚、从版本化资产重建与隐私 canary。结果只包含门槛名称与
   证据行，不含任何案情、事实或报告内容。

4. **新增“从版本化资产重建当前批次”能力**（`content/assets.ts`）。产品规格
   13.5 要求可从版本库或可导出结构化存储重建当前批次。资产以带格式版本的
   JSON 导出受治理内容种子，重建时经过结构校验与发布校验；不合法时抛出
   `ContentAssetError` / `ReleaseActivationError`，调用方必须保持上一批次。

5. **两类角色记录带非授权边界校验**（`acceptance/decisions.ts`）。内容批次
   确认与试行发布决定必须分别由不同角色记录，都必须包含“不代表法制审核、
   正式内容审定或机关授权”的声明，且不得出现暗示已正式审定或机关授权的表述；
   内容批次确认必须绑定当前激活批次。

6. **发布检查组合为一次可复现结果**（`acceptance/release-acceptance.ts` +
   `scripts/release-acceptance.ts`）。五个硬门槛分别对应内容与安全、验收矩阵
   覆盖、演练、人工设备记录与角色记录；任一失败时 `blocked` 为 true、脚本以
   非零退出码结束，并写入 `docs/acceptance/trial-release-result.json`。相同输入
   产生相同结果（生成时间可通过环境变量固定）。

7. **补齐两处规格交互缺口**。为满足规格 5.1 / 7.4 的“固定六模块索引”，报告页
   新增可访问的六模块索引导航（锚点跳转、明确可访问名称）；为满足规格 3.5 的
   “北京时间展示”，报告生成时间改用 `Asia/Shanghai` 并明确标注“（北京时间）”。

8. **浏览器验收同时提供自动化代理与人工门槛**。Playwright 新增 `wechat`
   project（Chromium + 微信 UA）运行核心流程；`mobile-safari`（WebKit）在
   `PM_ENABLE_WEBKIT_E2E=1` 时可运行，否则由真实 iPhone 人工记录把关。

## 后果

- 受控试行的开始条件从人工清单变为可机械核验、可复现的发布检查；场景不会
  被静默删除，也不会因代码已实现而默认满足门槛。
- 自动化能覆盖的部分（验收矩阵、演练、代理浏览器、可访问性与性能代理）在 CI
  中持续执行；真实设备、真实屏幕阅读器、真实 4G 与使用与数据说明的实际信息
  仍是人工/运维输入，未提供前发布检查明确阻断。
- 验收矩阵测试标题与测试源码字面绑定，重命名用例需要同步更新矩阵；这是刻意
  的，用于防止证据引用腐化。
- `docs/acceptance/` 下的结果文件是可复现的验收产物，不是产品运行时依赖；
  产品运行时不会读取测试文件或验收记录。
