# ADR-0015：报告生成增加流式纯文本模式，不做结构化校验

- 状态：已接受（结构化模式暂时保留作回退，验收通过后另行移除）
- 关联：部署说明见 docs/deployment/streaming-analysis.md。ADR-0004、0007、0009、0011、0012、0013、0014。在流式模式下，ADR-0013 第 3 条（“草稿引用不存在的法源或条号则整份不予采用”）与 ADR-0009、0011 的结构化六模块和研判速览不再适用。

## 背景

结构化报告要等模型写完整份 JSON、后端补全并校验后才一次性展示，加上提取一步，民警要等一两分钟才看到任何内容。目标交互是：一个案情输入框加一个结果文本框，文字实时逐段出现，按固定六个编号小节组织（见 GLOSSARY“流式分析文本”）。这与“先校验、后采用”的设计相冲突，只能取舍。

## 决策

1. 新增 `PM_REPORT_FORMAT=stream|structured`，未设置时，`llm` 模式默认 `stream`，其他模式默认 `structured`（现有 fixture/dify 行为与测试不变）。`structured` 保持现状，作回退。
2. 流式只在 `PM_PROVIDER_MODE=llm`（调用 `chat/completions` 的 `stream: true`）和 `fixture`（固定分块文本，供黑盒测试）下可用。`dify` 模式选 `stream` 时能力检查报不可用，失败关闭，不静默回退。
3. 新增无状态路由 `POST /api/v1/analysis/stream`，只收案情文本，以 SSE 回传。沿用匿名令牌、限流、并发和请求体大小限制。不创建会话，不做候选事实提取，不产生事实快照；服务器不保存案情和输出文本（ADR-0004），文本只在浏览器内存里，刷新即丢，“复制结果”是唯一留存方式。浏览器用 `fetch` 读流（要带匿名令牌请求头，不能用 `EventSource`）。
4. 模型输出纯文本，不要求 JSON，不做 Schema 校验和条号校验，也不做 `hydrateReportDraft`。后端仍把本次适用的受治理法源（含条文原文）放进提示词，要求只引用其中条文，以保留受治理内容项与内容发布批次的链路；这只是提供材料，不是校验。
5. 固定边界声明由后端在流结束时通过 `done` 事件追加，前端渲染在文本框下方，不经过模型。
6. 中断、停止或触顶：保留已出文字，标“内容不完整”，禁用复制，提供“重新生成”；不自动重试。点击“停止”时浏览器断开，后端同时中止上游调用。
7. 超时改为两条：空闲超时（上游连续无新内容，含首字等待，默认 30 秒）和总时限（沿用 `PM_REPORT_TIMEOUT_MS`），均可配置。输出体量上限沿用 ADR-0012 的思路，改按字符数截断。
8. 后端对 SSE 响应加 `X-Accel-Buffering: no` 与 `Cache-Control: no-cache`；部署文档加检查项：上线前在真实环境确认文字逐段到达，并核对 CDN 与负载均衡是否缓冲。
9. 遥测沿用只记数字的原则：耗时、首字延迟、字符数、是否中断/停止/触顶；案情与输出不进日志。新增字段须先进入 `ALLOWED_KEYS`，并通过隐私金丝雀测试。

## 已知风险

- **法条原文错引不再被系统拦截。** 模型可能写错条号、引用已废止条文，或在提示词材料之外凭记忆编造。民警必须自行核对。
- 没有事实快照，“系统提取，未经确认”的逐条标注和多事项拆分在流式模式下都不存在，由提示词要求模型把未查明、有争议的事实写成“待核实”，但这只是文字约定，不可验证。
- 这一决定削弱了受控试行版“内容版本治理、场景化验收”的前提，因此验收口径要补人工环节。

## 验收（在 ADR-0007 口径上增加）

- 首字延迟中位数 ≤ 10 秒；总耗时口径不变（中位 ≤ 90 秒、最大 ≤ 150 秒，至少 5 次，含短长案情）。
- 5 次运行里的法条引用，用虚构案情逐条人工比对仓库法源，结果记入 `docs/acceptance/manual-evidence.md`。

## 恢复校验的触发条件

验收或试用中出现任何一次对关键条文（条号、处罚幅度）的错引，就恢复后置校验：模型流完后，后端对文本中的条号引用与仓库法源比对，不符则在文本框下方显式标注。是否恢复由内容维护者决定。
