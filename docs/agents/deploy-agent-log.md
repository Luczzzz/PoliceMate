### 5.2 两个模型输出偏差模式（细节 · 修复 · 验证）

#### 模式一：末尾多余逗号（工作流自校验过严）

- 原始证据：

  ```
  json.decoder.JSONDecodeError: Illegal trailing comma before end of object: line 1 column 5391 (char 5390)
    → wrap 代码节点 json.loads 抛错
  ValueError: LLM 输出不是有效 JSON
  ```

- 频率：07:45 起近 3 小时 1 次 / 17 次运行；前一晚 19:38–19:49 另有 3 次同签名失败。
- 影响：**已经算好的报告被整份丢弃**，用户白等 90–290 秒，且客户端提示像网络问题，误导排查方向。
- **热修**：`wrap` 节点新增 `_strip_trailing_commas()`——状态机逐字符扫描，只删除「字符串字面量之外、紧随 `]` 或 `}` 的多余逗号」；**仅当修复后能解析成功**才接受，否则仍抛原错误。

#### 模式二：模型自创字段（后端严格校验导致整份作废）

- 原始证据（后端 AJV 按 `dify-report.json` 校验）：

  ```
  ['result','modules',3] → Additional properties are not allowed ('interviewItems_note' was unexpected)
  ```

- 关键事实：模型侧 `dify-report-result.json` **同样是** `additionalProperties: false`（25 个定义全部严格），**但模型没有遵守**——说明当前「结构化输出」通道并未真正强制 JSON Schema strict 模式，Schema 只是提示。
- **热修**：`wrap` 节点新增 `_prune()` + 形状树 `_SHAPES`（**由仓库 `dify-report-result.json` / `dify-extract-result.json` 自动生成**，含 `anyOf` → 对象分支合并），只丢弃白名单外的键、不改动已知键内容，并 `print()` 记录丢弃内容。

#### 确定性验证（直接执行节点代码 + 用后端 Schema 校验真实样本）

| 用例 | 结果 |
| --- | --- |
| 模块级自创字段（复现 07:52 那次） | 丢弃后按 `dify-report.json` **校验通过** |
| 深层自创字段：`traceLinks[i].basis` / `factReferences[i].value` / `quickBrief.nextSteps[i]` / `branchCards[i]` / 根级 | 全部丢弃，**校验通过**，无残留 |
| 合法报告样本 | 裁剪后 `result` 与输入**逐字一致**，**校验通过** |
| 提取路径：自创字段 / 合法样本 | 丢弃 / 逐字不变，`dify-extract.json` **均校验通过** |
| 末尾逗号（含代码围栏包裹） | 通过 |
| 字符串内部的 `,}`、转义引号 | 内容**原样保留**，不被误改 |
| 真正损坏的 JSON `{"a":,,}` | **仍然失败**（未放宽） |

### 5.3 仍未解决的风险（供你判断优先级）

1. **体量**：报告 27k–45k 令牌（目标 ≈15k）。干净条件下 62–100 秒，一旦有并发或重试立刻退化到 200–290 秒，而用户可感知硬上限是服务端 410 秒 / 前端 420 秒。
2. **重试放大**：重试另起运行 + 旧运行不可取消 → 争用 → 越重试越慢（事件 3、4）。体量没降下来前建议把尝试次数降为 1。
3. **形状树会过期**：`_SHAPES` 由你的 Schema 自动生成，**契约变更时必须重新生成**，否则裁剪白名单过期（不会误删合法字段，但会漏掉新的自创字段）。
4. **strict 模式缺失**：见模式二的关键事实。只要模型还能越界，就还会有新的失败形态。

### 5.4 请开发端处理（按重要性）

1. **把两处容错回写进 `docs/deployment/dify-workflow-build.md` 的 `wrap` 代码样例**——那是节点的权威来源。我这边是就地热修；文档不同步的话，下次照文档重建工作流会退回零容错版，今天这两类故障会原样复现。
2. **上游根治**：开启 JSON Schema strict 模式；或产品层明确「丢弃未知键」优于「整份作废」——现在一次模型手滑就浪费 90–290 秒并让用户看到失败。
3. **可观测性**：容忍目前只体现在 `print()`（Dify 节点日志可查）。建议把「本次容忍次数与丢弃字段」纳入验收输出，否则质量/体量回归会被静默掩盖。
4. **预算语义写进文档**：`PM_*_TIMEOUT_MS` 是含重试的总预算（单次尝试 = 总预算 ÷ 尝试次数）。规范里「提取 30 秒 / 报告 90 秒」在本机不成立，建议标注为「参考值·依环境调整」。
5. 若你希望用版本串区分这次节点热修，说一声，我提升为 `v1.2.1` 并同步 `PM_DIFY_WORKFLOW_VERSION`（当前保持 `v1.2.0`，因为契约与提示词未变）。
